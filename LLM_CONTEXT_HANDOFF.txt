=================================================================
1) EXECUTIVE SUMMARY
=================================================================

This repository is a Flask-based project used in two modes:

A) Local development mode (Flask server)
- Flask serves templates from templates/ and assets from static/.
- Routes like /, /tictactoe, /beforegta6 work through Flask route handlers.

B) Production mode on Netlify (static deploy)
- Netlify is NOT running Flask app.py.
- Netlify runs a build step that creates dist/ from templates/ and static/.
- Netlify publishes dist/.
- Friendly URL redirects are defined in netlify.toml.

Critical fact:
- For Netlify, all asset references in HTML must be absolute paths like /static/... (not ../static/...).

=================================================================
2) REPOSITORY STRUCTURE AND FILE ROLES
=================================================================

Root files:
- app.py
  Flask app used for localhost development and API endpoints (multiplayer + BeforeGTA6 data APIs).
- gameking.db
  Local SQLite database file created/used by app.py for social profiles, post events, and BeforeGTA6 posts.
- netlify.toml
  Netlify build + publish configuration and route redirects.
- netlify_build.py
  Build script used by Netlify to generate dist/.
- LLM_CONTEXT_HANDOFF.txt
  This handoff document.

Folders:
- templates/
  Source HTML pages used by Flask and copied into dist/ for Netlify.
  Key pages:
  - index.html
  - tictactoe.html
  - beforegta6.html

- static/
  Source static assets:
  - CSS: style.css, style_tictactoe.css, gtastyle.css
  - JS: background.js, tictactoe.js, tkbackground.js, script.js
  - Images/GIFs used across pages

- dist/
  Netlify deploy artifact generated by netlify_build.py.
  Contains:
  - dist/index.html
  - dist/tictactoe.html
  - dist/beforegta6.html
  - dist/static/... (copied from static/)

Important note:
- script.js currently exists but is empty. This is not an error.

=================================================================
3) HOW THE APP WORKS LOCALLY (FLASK)
=================================================================

Main page routes in app.py:
- / -> render_template('index.html')
- /tictactoe -> render_template('tictactoe.html')
- /beforegta6 -> render_template('beforegta6.html')

Before GTA 6 backend/API endpoints in app.py:
- /api/social-login
- /api/post-event
- /api/beforegta6/posts (GET + POST)
- /api/beforegta6/vote

Persistence behavior (new):
- app.py initializes SQLite tables on startup in gameking.db.
- beforegta6_posts is seeded with default posts via INSERT OR IGNORE.
- User-created BeforeGTA6 posts and votes persist across app restarts (as long as gameking.db is preserved).

Tic-Tac-Toe backend endpoints in app.py:
- /game/create_room (legacy host/join flow still present)
- /game/get_state/<room_code>
- /game/make_move
- /game/reset

Matchmaking endpoints (currently active frontend flow):
- /game/matchmaking/join
- /game/matchmaking/status
- /game/matchmaking/leave

Matchmaking behavior:
- In-memory FIFO queue.
- Pairs players into room codes.
- Stale clients cleaned after timeout.
- Not persistent across process restarts.

=================================================================
4) HOW PRODUCTION DEPLOYMENT WORKS (NETLIFY)
=================================================================

netlify.toml currently defines:
- Build command: python netlify_build.py
- Publish directory: dist
- Redirects:
  - /tictactoe -> /tictactoe.html
  - /beforegta6 -> /beforegta6.html

netlify_build.py behavior:
1. Deletes existing dist/ if present.
2. Creates new dist/.
3. Copies selected pages from templates/ to dist/ root.
4. Copies static/ to dist/static/.

Result:
- Netlify serves a standard static site structure.
- URLs resolve without needing Flask runtime.

Important production caveat:
- Netlify static hosting does not run app.py APIs.
- Any feature in beforegta6.html that calls /api/... requires a separate running backend service.

=================================================================
5) INCIDENT HISTORY (VERY IMPORTANT)
=================================================================

Production incident that happened:
- Netlify deployment succeeded but site rendered as plain text / broken UI.
- CSS, JS, canvas, and images appeared missing.

Root causes discovered:
1) Wrong publish directory configuration
- Netlify was configured to publish dist while no dist folder existed.
- Build command was empty, so nothing generated dist.

2) Pathing mismatch between Flask local and Netlify static serving
- HTML used relative asset paths like ../static/...
- Under Netlify redirects/static serving, these references resolved incorrectly.

Fixes applied:
1) Added deterministic Netlify build script: netlify_build.py
2) Configured netlify.toml to run that build and publish dist/
3) Updated templates to use absolute asset paths /static/... everywhere
4) Included dist in repo so deploy artifact exists as fallback

Why this solved it:
- Netlify always has a valid publish directory.
- Paths are stable regardless of route depth/redirect behavior.

=================================================================
6) NON-NEGOTIABLE DEPLOYMENT RULES
=================================================================

Rule 1: Do not use relative ../static paths in templates.
- Always use /static/... in HTML, inline JS constants, and image references.

Rule 2: If adding a new page, update BOTH:
- netlify_build.py PAGES list
- netlify.toml redirects (if friendly route needed)

Rule 3: Keep netlify.toml publish = dist and command = python netlify_build.py.

Rule 4: Validate generated dist before push when making major changes.

Rule 5: Do not rely on Flask runtime behavior for Netlify production.

=================================================================
7) SAFE CHANGE WORKFLOW FOR FUTURE LLMs
=================================================================

When changing UI/pages:
1. Edit files in templates/ and static/.
2. Ensure all references are /static/... absolute paths.
3. Run local check:
   - python netlify_build.py
4. Verify these exist:
   - dist/index.html
   - dist/tictactoe.html
   - dist/beforegta6.html
   - dist/static/style.css (and other needed assets)
5. Push to main.
6. Confirm Netlify deploy from latest commit and status Published.

When adding a new route/page (example: /newpage):
1. Add templates/newpage.html
2. Add "newpage.html" to PAGES in netlify_build.py
3. Add redirect in netlify.toml:
   from = "/newpage"
   to = "/newpage.html"
   status = 200
4. Run python netlify_build.py and verify dist/newpage.html exists
5. Commit and push

=================================================================
8) DIAGNOSTIC CHECKLIST IF SITE BREAKS AGAIN
=================================================================

If site looks unstyled or images missing:
1. Check deployed commit in Netlify Deploys tab.
2. Confirm netlify.toml still has:
   - build command python netlify_build.py
   - publish dist
3. Confirm dist contains HTML and static assets.
4. Search templates for bad relative paths:
   - ../static
5. Verify browser network requests are not 404 for:
   - /static/style.css
   - /static/js/background.js
   - /static/images/... used by page

If deploy fails with "Deploy directory 'dist' does not exist":
- Build command did not run or script failed.
- Verify netlify_build.py exists at repo root and runs successfully.

If pages load but friendly routes fail:
- Check netlify.toml redirects and syntax.

If multiplayer behaves oddly in production:
- Remember backend state is in-memory in app.py.
- Netlify static hosting does not run Flask backend by itself.
- Multiplayer requires a running Python backend endpoint service.

If Before GTA 6 feed/login/voting behaves oddly in production:
- Check browser network for /api/social-login, /api/post-event, /api/beforegta6/posts, /api/beforegta6/vote.
- If these are 404/failed on Netlify-only hosting, that is expected without a separate Flask backend deployment.
- Local Flask mode supports these endpoints and writes to gameking.db.

9) IMPORTANT TECHNICAL CONTEXT FOR FRONTEND FILES
=================================================================

index.html:
- Landing page with project circles and links to /tictactoe and /beforegta6.
- Uses p5.js and background.js for animated background.
- Defines global constants for assets:
  - PIXEL_BG_PATH
  - man_waving
  - Sheep

tictactoe.html:
- Contains menu + board UI.
- Loads tictactoe.js (game logic), tkbackground.js, and style_tictactoe.css.
- Has matchmaking status UI (waiting count, status indicator).

beforegta6.html:
- Heavier UI page with feed/panel/modal interactions.
- Uses style.css + gtastyle.css.
- Contains substantial inline JS for post rendering, modal behavior, social-login simulation, and create/vote flows.
- Calls backend endpoints (/api/social-login, /api/post-event, /api/beforegta6/posts, /api/beforegta6/vote).
- Includes client-side fallback/default post data, but persistent data comes from backend when available.

background.js:
- p5 sketch for homepage animated background and sprites.
- Depends on PIXEL_BG_PATH, man_waving, Sheep globals declared in HTML.

tictactoe.js:
- Full game controller class.
- Handles single-player, multiplayer matchmaking polling, board updates.
- Uses localStorage client id key for matchmaking identity.

=================================================================
11) WHAT NOT TO DO
=================================================================

- Do not switch Netlify publish directory back to root unless deployment model is redesigned intentionally.
- Do not revert templates to ../static references.
- Do not assume Flask-only behavior will match Netlify static output.
- Do not remove netlify_build.py without replacing it with another valid build pipeline.
- Do not assume /api/* endpoints work on static Netlify hosting without separately deploying Flask backend.
